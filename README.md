# 贪心链与 DoG · 演示动画

## 用途

两套演示共用一个播放器：

- **终版演示**（`final.html`）：约 47 分钟的正式演讲，论文式组织：摘要与引言 → 关键判断与权威来源 → DoG 与 DDoG → 贪心链与 skills 自迭代 → 时间线 → 一页实验结果 → 讨论。观众是只听过 Agent 概念、不了解它怎么工作和怎么评测的人。全部文字（页眉、字幕、讲稿）只写在 `talk/final/script.md`。
- **机制动画**（`index.html`，10 月 19 日版）：向技术同事讲解长程任务的 Agent 评测机制：为什么要有贪心链、一个单元里怎么加跑与终止、判定器怎么判、DoG 怎么组合结论与只重判变化的部分。字幕写在场景代码里。

两套都是每一页只讲一件事，演讲者按键逐步推进，每一步一段动画加一句字幕。

## 设计

- 一份演示 = 若干场景；一个场景 = 一张 1920×1080 的 SVG 画布 + 一条 GSAP 时间线，时间线切成若干步。
- 播放器负责翻页、字幕、进度、缩放、讲稿与演讲者视图；场景只负责画图与排动画，互相独立。
- 任何时刻的画面只由播放头位置决定：「上一步」和直接打开某一步，都是把播放头放到那一步的结尾，不需要每个场景自己写倒放逻辑。
- 画面停在某一步时也在动：场景可以登记常驻动画（光点流动、外圈扩散），背景有缓慢漂移的光；系统设置“减少动态效果”时两者都关闭。
- 终版的文字只有一个来源：讲稿 `talk/final/script.md`；画面里的原话与引文只从 `src/final/quotes.ts` 取，启动时逐条检查它们是否逐字出现在讲稿里。
- 构建产物是自包含的 HTML 文件，现场断网也能打开。

## 使用

```bash
bun install
bun run dev          # 开发：终版 http://localhost:5173/final.html，机制动画 http://localhost:5173/
bun run build        # 产物：dist/final.html 与 dist/index.html（单文件，可直接双击打开）
```

放映时按键：

| 按键 | 作用 |
|---|---|
| → / 空格 / PageDown / 鼠标左键 | 下一步；动画还在播时再按一次，直接跳到这一步的结尾 |
| ← / PageUp | 上一步（直接显示那一步的结尾） |
| Home / End | 本场景第一步 / 最后一步 |
| 0–9 | 跳到第 n 个场景 |
| O / Esc | 目录 |
| F | 全屏 |
| N | 在舞台上显示或隐藏这一步的讲稿（排练用） |
| P | 打开演讲者视图（另一个窗口：讲稿、画面说明、下一步字幕、计时；在里面按键会同步翻页） |

翻页笔一般发送 PageUp / PageDown，可以直接用。

网址参数：`#<场景 id>/<步号>` 直接打开某一步；`?only=<文件名>`（例如 `?only=05-judge`、`final.html?only=13-dog`）只加载一个场景，用于单独修改与预览；`?presenter=1` 是演讲者视图。

## 细则

### 目录

- `src/player.ts`：播放器（两套演示共用）。
- `src/main.ts`、`src/final/main.ts`：两套演示的入口。
- `src/scene.ts`：场景契约（`id`、`title`、`kicker`、`bare`、`build`；build 收到 `svg`、`tl`、`step`、`idle`、`title`、`kicker`）。
- `src/scenes/NN-<id>.ts`、`src/final/scenes/NN-<id>.ts`：两套演示的场景文件，按文件名顺序自动收集，新增场景不必改注册表。
- `src/notes.ts`：讲稿解析（格式写在文件开头与 `talk/final/script.md` 的“读法”一节）。讲稿的一级标题是章，每个场景记下自己所在的章。
- `src/final/chapter.ts`：章节页。`src/final/scenes/NN-ch-*.ts` 各调用一次 `chapterScene(id)`；章节目录取自讲稿的一级标题，终版页眉左上角显示当前所在的章。
- `src/final/quotes.ts`：终版画面里出现的原话与引文，以及按显示宽度折行的 `wrap()`。
- `talk/final/script.md`：终版讲稿，也是终版全部文字的唯一来源；附录有原话出处、名词表、改动清单、待确认事项、数据来源。
- `src/lib/svg.ts`：造元素的函数（文字、卡片、标签、路径、图标）。
- `src/lib/fx.ts`：动画函数（出现、弹出、画线、变色、压暗、沿路径流动、换文字）。
- `src/theme.ts`：画布尺寸、颜色与字号。

### 写场景的规则

播放器靠跳到某一步的结尾来实现上一步，所以时间线必须是确定的：

1. 先造好全部元素，需要先隐藏的在构建时用 `gsap.set(..., { autoAlpha: 0 })`。
2. `step()` 之后追加的补间属于这一步；第一步之前不能有补间。机制动画写 `step('字幕')`；终版的字幕在讲稿里，写 `step()`，场景也不写 `title` / `kicker`——两处都写会抛错，讲稿条目数与步数不一致也会抛错。
3. 元素第一次出现用 `appear / pop / fadeIn / draw`，之后的变化用 `tl.to / recolor / refill / dim / pulse`。
4. 换文字用 `swapText`，不要在回调里改 `textContent`；数字滚动对 `<tspan>` 做 `textContent` 补间。
5. 虚线路径用 `fadeIn`，`draw` 会改写虚线样式。
6. 常驻动画用 `idle(loop => …)`，登记在当前步上：播完这一步后循环，退回更早的步时回到第 0 秒的状态并暂停。它只能动自己专用的装饰元素，不能动主时间线控制的元素与属性；第 0 秒必须是不可见或静止的样子（用 `fromTo`）。样板见 `src/final/scenes/00-cover.ts`。

动画区为 x 96–1824、y 170–890；页眉与字幕条由播放器绘制。颜色语义固定：绿色通过、红色不通过、琥珀色无法观察或证据不足、浅蓝冻结副本、蓝色运行中、紫色判定器与 DoG、粉色人工介入。

### 截图检查

开发服务器运行时，在浏览器控制台里：

```js
window.deck.list()                // 各场景的步数（同时检查讲稿条目数）
window.deck.show('judge', 3)      // 显示 judge 场景第 3 步的结尾
window.deck.audit()               // 当前画面里文字互相压住、文字压线的位置；干净时是 []
```
